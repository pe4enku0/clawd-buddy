# Clawd Notch — режим «Чёлка» для Clawd Buddy (macOS)

Это техзадание для Claude Code. Работаем в репозитории `clawd-buddy`, только в папке `macos/`.
Windows-версию (`windows/`) не трогаем.

## Кто я и где это запускается

- Я почти не программирую. Объясняй простыми словами, что мне нужно сделать руками (нажать, разрешить, перезапустить).
- Это школьный MacBook **с чёлкой (вырезом под камеру)** под управлением **Jamf School**: нет прав администратора, App Store и Xcode недоступны.
  Есть только Command Line Tools (Swift, `swift build`). Сборка — как сейчас в `build.sh` / `install.sh`.
- Jamf может запретить разрешения «Запись экрана», «Универсальный доступ» (Accessibility) и «Микрофон».
  **Ничего не должно ломаться без этих разрешений** — только аккуратно отключаться с понятной подсказкой.
- Никаких попыток обойти Jamf, профили или ограничения системы.

## Идея

Сейчас краб Clawd живёт в углу экрана и реагирует на Claude Code через хуки.
Нужен второй режим: краб переезжает **в чёлку MacBook**. Чёлка «оживает»: расширяется в стороны, когда агент работает, и опускается вниз карточкой, когда нужно что-то показать (как приложения для чёлки на Mac и Dynamic Island на iPhone).
В настройках появляется переключатель **«Режим: Угол / Чёлка»**. Режим «Угол» должен работать как раньше, ничего в нём не ломаем.

Используем всё, что уже есть: спрайт и анимации краба (`BuddyView`), логику настроений (`Brain`), фразы (`Strings`, EN/RU), существующие хуки и способ доставки событий от Claude Code в приложение.

## Дизайн

Стиль — **чистый Apple**: как родной элемент macOS / Dynamic Island. Никаких градиентных фонов, лишних рамок и «самодельного» вида. Дизайн уже согласован на макете, ниже — точные правила.

### Геометрия чёлки

- Реальный размер выреза бери из системы, не хардкодь: высота = `NSScreen.safeAreaInsets.top`, ширина = ширина экрана − ширина `auxiliaryTopLeftArea` − ширина `auxiliaryTopRightArea`.
- Наш элемент **приклеен к верхнему краю экрана** и всегда ровно по центру выреза. Верхние углы прямые, **нижние скруглены**.
- На верхних углах — маленькие вогнутые «плечи» радиусом ~8 pt (как у настоящего выреза), чтобы чёлка плавно переходила в край экрана.
- **Середина над камерой — мёртвая зона**: в компактном виде ничего не рисуем поверх выреза, контент только в «крыльях» слева и справа.
- Цвет — **чистый чёрный `#000000`**, сливается с вырезом.
- Нет выреза (внешний монитор, другой Mac) → та же форма, просто приклеена к верхнему краю по центру экрана, ширина «выреза» ≈ 185 pt.

### Размеры (pt)

`N` — ширина выреза, `H` — высота выреза.

| Состояние | Ширина | Высота | Радиус низа |
|---|---|---|---|
| Компактное (покой, работа, ошибка) | N + 2×34 | H | 10 |
| Сон | N + 2×26 | H | 10 |
| Наведение | 360 | H + 58 | 26 |
| Подтверждение | 380 | H + 110 | 30 |
| Готово | 320 | H + 52 | 24 |
| Чат: думает | 360 | H + 56 | 26 |
| Чат: ответ | 400 | H + 150 (по содержимому, макс. 260) | 30 |
| Файл над чёлкой | 360 | H + 58 | 26 |

В раскрытых состояниях верхняя полоса высотой `H` (на уровне выреза) остаётся пустой, содержимое — под ней.

### Цвета и шрифты

- Шрифт — только системный (SF Pro), моноширинный — SF Mono (`.monospaced`).
- Заголовок: 15 pt semibold, белый. Подзаголовок: 12.5 pt regular, `rgba(235,235,245,0.6)` (как `secondaryLabel` в тёмной теме).
- Акценты — только системные цвета, по смыслу:
  - оранжевый `#FF9F0A` — агент работает / нужно действие;
  - зелёный `#30D158` — готово;
  - жёлтый `#FFD60A` — ошибка;
  - серый `#48484A` — покой.
- Кнопки внутри: тёмные `#1C1C1E` / `#2C2C2E`, главная кнопка — оранжевая с чёрным текстом. Кнопки — капсулы или круги, без рамок.
- Иконки — SF Symbols.

### Обводка — «чёлка работает»

Чёлка чёрная, но состояние видно по тонкой обводке **1.5 pt только по бокам и снизу** (сверху — край экрана, там обводки нет):

| Когда | Обводка |
|---|---|
| Агент работает (Edit/Write/Bash/Read/поиск), ИИ думает | бегущая «комета»: `AngularGradient` от прозрачного к оранжевому и жёлтому, крутится по кругу ~2.2 с на оборот |
| Нужно подтверждение, файл над чёлкой | сплошная оранжевая, «дышит» прозрачностью 30% → 100%, ~1.3 с |
| Готово | одна зелёная вспышка ~1.6 с, затаёт |
| Ошибка инструмента | одна жёлтая вспышка ~1.1 с |
| Покой, сон, наведение, ответ | обводки нет |

### Анимации

- Все изменения размера и формы — **пружина с заметным отскоком**: `.spring(response: 0.45, dampingFraction: 0.65)` (подбери на глаз, чтобы ощущалось как Dynamic Island).
- Содержимое при смене состояния появляется так: прозрачность 0 → 1, размытие 6 → 0, масштаб 0.94 → 1, с задержкой ~0.15 с после начала расширения. Уходит так же быстрее и без задержки.
- Значки справа в компактном виде появляются «поп»-эффектом (масштаб 0 → 1 пружиной).

| Состояние | Слева | Справа / содержимое |

Реакции краба на события берём из существующей таблицы clawd-buddy (Edit/Write → печатает, Read → читает, Grep/Glob/Web → бегает, Bash → бежит на месте, Stop → прыгает и т.д.).

### Окно

- `NSPanel`, `.nonactivatingPanel`, без иконки в Dock, уровень выше строки меню, на всех рабочих столах, **не забирает фокус**.
- Окно не должно мешать кликам вокруг чёлки: либо размер окна = размер чёлки, либо клики мимо формы проходят насквозь.
- Наведение мыши отслеживай без Accessibility (tracking area на своём окне).
- Прячется, когда активное приложение в полноэкранном режиме (игры, видео), и появляется обратно при выходе.

## Подтверждение действий (кнопки в чёлке)

Важно: **не мешать**.

- Когда Claude Code просит разрешение, чёлка мягко опускается (без звука, без кражи фокуса) и показывает команду и кнопки, как в таблице выше.
- Если я ничего не нажал за ~20 секунд — чёлка сворачивается в компактный вид, обводка продолжает «дышать» оранжевым как напоминание, а решение остаётся за терминалом как обычно.
- Нажатие по кольцу-таймеру = «отвечу в терминале»: чёлка сворачивается сразу.
- Реализация: синхронный хук на запрос разрешения (проверь по документации, `PermissionRequest`), который ждёт ответ от приложения с таймаутом. Нет ответа / приложение закрыто / ошибка → хук завершается **без решения**, и Claude Code спрашивает в терминале как обычно. Ни в коем случае не разрешать что-либо по умолчанию.
- Остальные хуки остаются асинхронными, как сейчас.
- Принимать решения можно только от своего приложения: если события ходят по сети/сокету — тот же подход с секретным токеном, что в Windows-версии.
- В настройках: галочка «Кнопки подтверждения в чёлке» (по умолчанию включена).

## ИИ в чёлке

Все запросы к ИИ идут через локальный `claude -p` (я уже залогинен в Claude Code, API-ключ не нужен).

Обязательно:
- Эти внутренние вызовы **не должны триггерить хуки краба** (иначе он будет реагировать сам на себя). Например: запускать с переменной окружения `CLAWD_NOTCH_INTERNAL=1`, а хук-скрипт игнорирует события, если она выставлена. Проверь, что это работает.
- Внутренним вызовам разрешён только инструмент чтения (Read). Никакого редактирования файлов и запуска команд. Флаги сверь с `claude --help`.
- Запуск в отдельной временной папке, не в моих проектах.
- Пока ждём ответ — состояние «Чат: думает». Если получится — показывать ответ по мере генерации (stream), если нет — целиком.
- Ошибки (нет `claude` в PATH, не залогинен, нет интернета) → понятное сообщение в чёлке на моём языке.

### 1. Чат по хоткею

- **Option+Space** — чёлка опускается в режим чата с полем ввода, фокус в поле.
- Хоткей через Carbon `RegisterEventHotKey` (ему не нужен Accessibility).
- Enter — отправить, Esc — закрыть. У ответа есть «Скопировать» (по наведению или правому клику, чтобы не загромождать).
- Внутри одного открытия можно продолжать разговор (передавать предыдущие сообщения как контекст или использовать продолжение сессии — как надёжнее).
- Хоткей меняется в настройках.

### 2. Перетащить файл на чёлку

- Когда тащишь файл к верху экрана, чёлка раскрывается в состояние «Файл над чёлкой».
- Поддержка: текстовые файлы, код, `.md`, `.pdf`, картинки (`.png/.jpg`).
- Отпустил → короткий пересказ (3–5 предложений) в виде ответа + поле, чтобы задать вопрос по этому файлу.
- Слишком большой файл → предупредить и взять начало.

### 3. «Что у меня на экране?»

- **Option+Shift+Space** (или кнопка при наведении) → краткое описание того, что на экране, и поле для вопроса («что значит эта ошибка?»).
- Способ 1: снимок экрана (ScreenCaptureKit или `screencapture -x` во временный файл). Нужно разрешение «Запись экрана».
- **Способ 2 (если разрешения нет или Jamf его запретил):** чёлка показывает подсказку «Нажми ⌘⌃⇧4 и выдели область» и сама забирает картинку из буфера обмена, как только она там появится (буфер обмена не требует разрешений).
- Определи, есть ли разрешение, и сам выбери способ. Не дёргай системный запрос разрешения больше одного раза.
- Скриншоты удалять сразу после ответа.
